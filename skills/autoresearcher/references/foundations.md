# Autoresearch Foundations — Cited Mechanics

The research base behind every rule in `SKILL.md`. Each entry = **what to steal**, not a summary. Read this when you need the *why* behind a loop mechanic, or to justify a design choice. Hype is flagged so you don't over-trust a headline.

> **The one finding that governs everything:** a generate→eval→keep loop with a single fitness signal is a *deceived hill-climber* — it converges onto one local optimum and erases the variation that hadn't paid off yet. Every serious system fixes this two ways: a **diversity-preserving archive** (so good-but-different candidates can't be deleted) and **reflective, trace-grounded mutation** (so proposals beat a specific incumbent instead of being random). Those two are the difference between this skill and a naive optimizer.

## 1. The core loop (generate → frozen-eval → keep-winner)

| Reference | Link | Mechanic to steal |
|---|---|---|
| **FunSearch** (DeepMind, Nature 2023) | [nature](https://www.nature.com/articles/s41586-023-06924-6) · [code](https://github.com/google-deepmind/funsearch) | Freeze the skeleton, evolve **one small function**. The **frozen `evaluate()` is the only ground truth** — non-running or lower-scoring candidates are dropped, no LLM opinion. **Island model** (`num_islands≈10`) + **periodic worst-half reset** (`reset_period≈4h`, reseed each killed island from a survivor's best) is the proven anti-collapse engine. **Best-shot prompting** (`functions_per_prompt=2`): show k prior programs sorted worst→best, ask for a better one — the improving sequence teaches direction. **Within-island diversity = signature clustering**: bucket programs by their per-test-input score *signature*, select via softmax over cluster scores, then favor the **shorter** program (parsimony tiebreak) — this is what stops an island filling with near-duplicates. Eval is the bottleneck → run **many more evaluators than samplers** (≈140 vs 15), async. **Sawtooth temperature** anneals explore→exploit repeatedly. Verified: new cap-set in dim 8, bin-packing beating best-fit. |
| **OPRO** ("LLM as optimizer", DeepMind ICLR 2024) | [arxiv](https://arxiv.org/abs/2309.03409) | The **leanest loop**, copy its defaults: meta-prompt = problem + best ~20 candidates **sorted ascending by score** (best nearest the generation point), ask for a better one; **8 candidates/step**, **temp 1.0**. The ranked trajectory *is* the no-repeat memory. ⚠️ Fragile — **largely fails with a weak optimizer model**; modest gains (GSM8K 71.8→80.2). |
| **AlphaEvolve** (DeepMind 2025) | [arxiv](https://arxiv.org/abs/2506.13131) · [blog](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/) | **Diff-based edits** (SEARCH/REPLACE on marked EVOLVE-BLOCKs), not full rewrites — mirrors edit-don't-rewrite, scales past one function. **Cascade evaluation** (cheap filter first, expensive eval only on survivors). **Cheap+expensive model ensemble** (Flash breadth + Pro depth). **Multi-metric Pareto keep** if the scorer has several axes. Verified: 4×4 matmul in 48 mults (beat Strassen's 49), real production speedups. ⚠️ ~75% of its math results are *re-discovery*; only works where an automated evaluator + human-marked blocks exist. |
| **AIDE** (Weco AI 2025, SOTA on MLE-bench) | [arxiv](https://arxiv.org/abs/2502.13138) · [code](https://github.com/WecoAI/aideml) | Three operators: **draft** (fresh diverse solution), **debug** (repair a buggy node, bounded depth), **improve** (**exactly ONE atomic change** → the metric delta is attributable = clean credit assignment). Node-selection is greedy-hill-climb-the-best-node, not MCTS. Feed back a **compact summary** (metrics + params tried + hints), never raw transcripts. The atomic-change rule is the genuinely valuable bit. |
| **Karpathy autoresearch** + autosearcher (2026) | [overview](https://thenewstack.io/karpathy-autonomous-experiment-loop/) · [skypilot](https://blog.skypilot.co/scaling-autoresearch/) | Minimal harness: an instruction `.md` + a frozen metric + an append-only `results.tsv` (so the agent never repeats) + keep/revert. ⚠️ Single-stream form is **admittedly greedy hill-climbing**; the community fix is **parallel factorial waves** (test a grid per wave, not one edit) — ~9× faster to the same optimum and resists local optima. |
| **DSPy** MIPROv2 / Bootstrap (Stanford) | [docs](https://dspy.ai/api/optimizers/MIPROv2/) | The metric **never changes** during optimization — only the artifact moves (your "never touch eval" rule, formalized). Instruction proposals are **grounded** in a data summary + code summary + bootstrapped demos, never blind. Bootstrap self-labels demos by keeping only traces that pass the metric. Least-hyped, most directly usable. |

## 2. Diversity preservation — why a single best is a trap

| Reference | Link | Mechanic to steal |
|---|---|---|
| **Novelty Search** — "Abandoning Objectives" (Lehman & Stanley 2011) | [pdf](https://www.cs.swarthmore.edu/~meeden/DevelopmentalRobotics/lehman_ecj11.pdf) | **The deception argument:** an objective defines a landscape with deceptive local optima — the gradient that *looks* like progress points away from the stepping stones you need. "The stepping stones to an ambitious goal rarely resemble the goal." Reward **behavioral sparseness** (k-NN distance in *behavior* space, k≈15) against a permanent archive. Deceptive maze: novelty 39/40, fitness-greedy 0/40. |
| **MAP-Elites** (Mouret & Clune 2015) | [arxiv](https://arxiv.org/abs/1504.04909) | Discretize a **behavior-descriptor** space (separate from fitness) into a grid; keep **one elite per cell**; a new candidate can only evict *its own cell's* incumbent. Distant high-performers are **structurally protected** — diversity by construction. Elites in one cell seed neighbors → progress chains through intermediates a single-objective search discards. |
| **GEPA** — Reflective Prompt Evolution (ICLR 2026 oral) | [arxiv](https://arxiv.org/abs/2507.19457) · [code](https://github.com/gepa-ai/gepa) | **Pareto archive over per-instance scores**: keep every candidate that is best on **≥1 eval case**; sample parents weighted by win-count. A naive "keep best *average*" discards specialists that uniquely crack a hard subset → trapped on one peak. **Reflective mutation**: run candidate → capture full trace → LLM diagnoses the failure in NL → targeted edit. The rich trace = "the text analogue of a gradient." **System-aware merge/crossover** for multi-module pipelines: take two frontier candidates, combine modules by lineage (a module refined in A but untouched in B → take A's) — module-respecting crossover beats blind splicing. ⚠️ "35× fewer rollouts" is best-case sample-efficiency; average win is single-digit; 4 tasks, not independently replicated. |
| **EoH** — Evolution of Heuristics (ICML 2024 oral) | [arxiv](https://arxiv.org/abs/2401.02051) | **Thought+code co-evolution** (NL idea then code; ablation: with-thought 0.66% gap vs code-only 2.57%). Five operators that force exploration: **E1** big-jump-different, **E2** recombine-shared-idea, **M1** refine, **M2** param-tune, **M3** simplify. Beat FunSearch with ~2k LLM calls vs ~1M. |
| **OpenEvolve** (OSS AlphaEvolve) | [code](https://github.com/codelion/openevolve) | Battle-tested defaults: 5 islands, migrate every 50, MAP-Elites on `[complexity, diversity]`, sampling split exploitation 0.7 / exploration 0.2 / elite 0.1, cascade thresholds `[0.5, 0.75, 0.9]`, **LLM-judge OFF by default** (real metric stays primary). |

## 3. Experiment selection & statistical honesty

| Reference | Link | Mechanic to steal |
|---|---|---|
| **UCB1 / Thompson Sampling** | [ucb](https://people.maths.bris.ac.uk/~maajg/teaching/stochopt/ucb.pdf) · [TS tutorial](https://arxiv.org/pdf/1707.02038) | Few discrete strategy-families → bandit, ~10 lines, no model. **UCB1**: `argmax μ̂_i + √(2 ln t / n_i)`. **Thompson (Beta-Bernoulli)**: `Beta(α,β)` per arm, sample θ, play argmax, α+=1 on win / β+=1 on loss — exploration self-anneals, zero knobs, trivially parallel. Reward = did-this-engine-improve-the-metric. |
| **Bayesian opt / TPE** (Optuna) | [distill](https://distill.pub/2020/bayesian-optimization/) | Medium mixed/categorical space → **TPE**: split evals into good/bad, fit densities, pick x maximizing `l(x)/g(x)`. ⚠️ GP-BO is O(n³), brittle in high-dim/categorical — don't reach for it on a small space. |
| **Hyperband / ASHA** | [arxiv](https://arxiv.org/abs/1603.06560) · [asha](https://arxiv.org/abs/1810.05934) | Have a **cheap-fidelity proxy** (eval on a 100-case subset that ranks like the full set)? Start many configs cheap, kill the worst `1−1/η` each rung, promote survivors. ⚠️ Silently assumes the proxy ranks like full budget — a slow-starter gets murdered early. |
| **MLE-bench** — pass@k (OpenAI 2024) | [arxiv](https://arxiv.org/abs/2410.07095) | **Repeated sampling is a free lever**: o1+AIDE 16.9% medals @pass@1 → **34.1% @pass@8** — doubling the win rate just by taking k independent shots and keeping the best. **Scaffold > base model** (AIDE 8.7% vs OpenHands 4.4%, same model). ⚠️ pass@k is k× compute (selection, not a smarter agent) and assumes a **trustworthy held-out selector** — select on validation, never the frozen test, or pass@k becomes overfitting-by-resampling. Don't let the agent self-terminate; run to a fixed budget, return best-by-validation. |
| **Reflexion / Self-Refine / CRITIC** | [reflexion](https://arxiv.org/abs/2303.11366) · [self-refine](https://arxiv.org/abs/2303.17651) · [critic](https://arxiv.org/abs/2305.11738) | Self-refinement loops work **only when gated by a non-fakeable external verifier** (tests, env reward, exact-match, a real held-out metric). Feedback must be **structured/actionable** (names the defect + fix), not "is this good?". Saturates at **~3 rounds**. |
| **"LLMs Cannot Self-Correct Reasoning Yet"** (Huang, DeepMind 2023) + **Kamoi survey** (TACL 2024) | [huang](https://arxiv.org/abs/2310.01798) · [kamoi](https://arxiv.org/abs/2406.01297) | **The negative lesson:** *intrinsic* self-correction (no external signal) **fails and often degrades** accuracy. The bottleneck is error *detection*, not fixing — given the location, models can fix it. **Operational rule: before adding any reflect/refine loop, name the external verifier that gates it. If you can't name one cheaper than the task, don't build the loop.** |
| **Statistical honesty bundle** | see `statistics.md` | Noise floor `σ=√(p(1−p)/n)`; **paired McNemar** for @1, paired bootstrap for @k/judge; **Ladder promotion** (crown a champion only if it beats best by >1σ, ideally 2σ — Blum & Hardt 2015); **garden-of-forking-paths** selection bias `≈σ·√(2 ln m)` (Gelman & Loken); equal tuning effort per arm (Henderson "Deep RL that Matters"). |

## 4. Diagnosis / root-cause attribution

| Reference | Link | Mechanic to steal |
|---|---|---|
| **Who & When** — failure attribution (ICML 2025) | [arxiv](https://arxiv.org/abs/2505.00212) | **The reality check:** automated failure attribution is **~53% at the component level, ~14% at the decisive-step level — some methods below random.** Your diagnosis stage is the riskiest part of the loop. "**Decisive error**" = counterfactual: the step where, if replaced by a correct action, the trajectory would then succeed. Localize *where* by **binary-searching the trajectory**, and **calibrate trust accordingly** — never auto-dispatch a fix off a single-pass pinpoint. |
| **5 Whys / Fishbone / FTA** (classic RCA) | [compare](https://fivewhys.ai/blog/root-cause-analysis-methods-compared) | Use all three as **phases**, not alternatives. **Fishbone** enumerates candidate cause-buckets (so you don't tunnel on the first). **5 Whys** drills the dominant bucket to a systemic root. **FTA** models *conjunctive* failures (fails only when A AND B co-occur) via minimal cut-sets. Each fails alone: 5 Whys assumes one linear chain & isn't reproducible; Fishbone produces a ranked-nothing list; FTA needs a known failure model. Phrase as **"what conditions made this possible"** (Salesforce "how not why") — mechanism, not blame-story. Then validate by toggling. |
| **Ng, ML Yearning** — error analysis | [pdf](https://home-wordpress.deeplearning.ai/wp-content/uploads/2022/03/andrew-ng-machine-learning-yearning.pdf) | **This is the diagnoser.** Sample ~100 failing eval cases, one row per failure × one column per hypothesized cause (multi-tag), **compute each cause's ceiling** (% of misses it touches). The controller picks the engine by **highest ceiling × tractability** — not the most recent or most annoying bucket. Near-zero hype, decades validated. |
| **Errudite** (ACL 2019) | [paper](https://aclanthology.org/P19-1073/) | Make each failure bucket a **re-runnable query** over the error set, not an anecdote — reproducible and testable. After a fix, **re-run the same query** to confirm that bucket shrank (and check it didn't reappear elsewhere): this is your fix-validation primitive and standing-slice regression detector. |
| **Domino** — slice discovery (ICLR 2022) | [arxiv](https://arxiv.org/abs/2203.14960) | **Embed → Slice → Describe** with two acceptance gates: a cluster is real only if it is **(a) high-error AND (b) coherent / nameable in one sentence**. **Reject any cluster you can't name** — it's noise. ⚠️ Slice discovery is imperfect (~36% recall, surfaces artifacts) — treat a cluster as a candidate, not a finding. |
| **MAST** — failure taxonomy (NeurIPS 2025) | [arxiv](https://arxiv.org/pdf/2503.13657) | Build a **fixed, empirically-derived taxonomy first, then auto-classify each miss into it** — a *frozen* taxonomy makes bucket counts comparable across iterations. Key finding: **"failures with similar surface behaviors stem from different root causes"** — cluster on cause, not appearance. |
| **Counterfactual / Causal-graph RCA** (ECML 2024) | [arxiv](https://arxiv.org/abs/2406.08106) | **The truth gate that cuts through every bias:** intervene on the hypothesized cause alone; if the failures disappear, it's the cause; if not, you mis-attributed. Same definition as Who&When's decisive error. *Plausible explains the past; correct predicts the intervention.* |

**Biases the diagnoser exhibits (actively block them):** last-touched bias (blame the final stage when an upstream one broke it — credit assignment is *delayed*), anchoring on the first hypothesis, single-cause fallacy on a multi-factor miss, correlation≠causation, and acting on an un-nameable cluster. Generator ≠ diagnoser ≠ judge (self-correction blind spot — models miss their own errors but catch identical ones in external content).

## 5. Loop control

| Reference | Link | Mechanic to steal |
|---|---|---|
| **Anthropic — Building Effective Agents** (2024) | [link](https://www.anthropic.com/engineering/building-effective-agents) | Your controller = **Orchestrator-Workers where the orchestration decision IS the diagnosis**, wrapped in an **Evaluator-Optimizer** outer loop, with **generator ≠ evaluator ≠ diagnoser**. "Include stopping conditions to maintain control"; "gain ground truth from the environment at each step"; add complexity only when it demonstrably helps. |
| **GEPA loop-control triad** | [arxiv](https://arxiv.org/abs/2507.19457) | Copy wholesale: **patience = 3** no-gain iters → stop; **max-iters cap** (default ~5–30); **disjoint held-out set the engines never see**, used only at promotion. ⚠️ **Validated overfitting:** 20–100 examples beat 500; test performance **peaked at steps 4–7 then degraded** — more iterations ≠ better; the patience/held-out gates exist to catch exactly this. |
| **Adaptive Operator Selection via bandits** (DYTS) | [arxiv](https://arxiv.org/abs/2004.10874) | When diagnosis confidence is low, fall back to a **bandit over engines**: reward each by the eval delta it produced, use **windowed/decayed rewards** (an exhausted engine gets demoted), add **change-detection** so the controller re-explores when the landscape shifts. |
| **Goodhart / specification gaming** | [reward hacking](https://en.wikipedia.org/wiki/Reward_hacking) | A frozen eval + per-iteration optimization is **Goodhart by construction**. Three defenses: (1) score promotion on a **held-out the loop is not optimized against**; (2) **multi-metric agreement** — gaming one metric usually breaks another; (3) **regression trip-wire** — if any standing slice regresses while the aggregate rises, **halt and inspect** (that's the overfitting signature). |
| **Agent loop guardrails** | [guide](https://docs.bswen.com/blog/2026-03-11-prevent-ai-agent-infinite-loops/) | Stopping must be **external and deterministic — the controller does not get a vote.** Mandatory guards: max-iteration cap, no-progress detection, token/cost budget, oscillation detection (same diagnosis→engine→delta twice = stuck). Most well-defined tasks finish in **10–30 iterations**. |

## 6. Novel & tangential ideation (engine-specific)

| Reference | Link | Mechanic to steal |
|---|---|---|
| **"Can LLMs Generate Novel Research Ideas?"** (Si et al., Stanford 2024) | [arxiv](https://arxiv.org/abs/2409.04109) | **Two hard limits to design around.** (1) **Duplication ceiling:** ~4000 raw ideas → only ~5% unique; non-duplicate count **plateaus** — raw resampling does NOT scale novelty. (2) **LLM-as-novelty-judge is unreliable** (~53% agreement, *below* the human floor) — never trust an LLM's self-rating of novelty. Over-generate then **rerank by pairwise tournament** (validated ranker), not absolute scores. RAG-ground each generation in ~10 retrieved papers. |
| **Google Co-Scientist** (2025, multi-agent) | [blog](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/) · [arxiv](https://arxiv.org/abs/2502.18864) | **Elo tournament via pairwise debate**: hypotheses compete in simulated debates; win/loss updates a **persistent Elo**; the loop optimizes Elo. **Proximity agent = dedup engine**: a similarity graph clusters hypotheses, prevents near-duplicates, AND seeds matchups (make *similar* ones compete to resolve real distinctions). **Evolution mutates only the top of the board**; offspring must win their own Elo. **Meta-review** synthesizes recurring critique patterns across all debates → biases the next generation. Most compute goes to **verification**, not generation. ⚠️ Wet-lab validation = 3 cherry-picked cases; the broad pool is scored only by self-generated Elo → anchor any self-judge to an external signal. |
| **Sakana AI Scientist** v1/v2 | [v1](https://arxiv.org/abs/2408.06292) · [v2](https://arxiv.org/abs/2504.08066) · [critique](https://arxiv.org/abs/2502.14297) | **Structured idea object** (steal the schema): `{Name, Title, Experiment-outline, self-scores}`, refined over ~5 reflection passes before acceptance. **Growing idea archive** — new ideas generated as explicit extensions of/comparisons to what's already there (the internal dedup memory). **Novelty gate**: each idea checked against literature (Semantic Scholar/OpenAlex); high-similarity → discarded, carries a binary `novel` flag. v2 adds **best-first tree search** with `max_debug_depth`/`debug_prob` (failing nodes get bounded debug, not discarded). ⚠️ Self-assigned 1–10 scores by the *same* model → optimistic/gameable; workshop-tier output; **documented self-modification** (edited its own script to extend its timeout) → **sandbox and cap runtime externally**. |
| **Nova** — goal-directed retrieval | [arxiv](https://arxiv.org/abs/2410.14255) | Each round, plan *what knowledge you need to be more novel* → retrieve → generate → self-filter. 3.4× more unique-novel ideas than blind retrieval. ⚠️ No gain past ~3 iterations. |
| **Novelty by absence** | [arxiv](https://arxiv.org/abs/2504.09389) | Most defensible novelty metric: **Originality** = fraction of high-order n-grams absent from the training corpus × **Quality** = task judge, combined by harmonic mean (punishes both garbage-original and polished-memorized). Minimum viable: **dedup against prior attempts by embedding similarity** (cosine ≥0.8 = duplicate, kill it). |
| **Structure-Mapping / SME** (Gentner) | [smt](https://en.wikipedia.org/wiki/Structure-mapping_theory) | A *good* analogy maps **relations, not attributes**, and wins by **systematicity** (deep connected structure). The candidate inference = the unmapped-but-connected source structure **projected onto the target** — *that projection is the new idea.* |
| **Analogy mining** (Hope/Shahaf/Kittur, KDD 2017) | [arxiv](https://arxiv.org/abs/1706.05585) | Operationalizes tangentiality as a query: represent items as **(purpose, mechanism)**; a structural analogy = **high purpose-similarity + LOW mechanism-similarity** ("same problem, different domain"). |
| **TRIZ / Conceptual Blending / Bisociation** | see `cross-domain-map.md` | TRIZ contradiction matrix = a precomputed abstract-problem→cross-domain-solution index. Blending = project two inputs into a blend with emergent structure, verify by **optimality principles**. Swanson ABC = bridge two disjoint literatures. |

**The verification half is the whole game.** Both LLMs and eager humans will hand you a beautiful analogy that is pure surface. Gate every cross-domain mapping on: **systematicity** (a *system* of relations aligns, not isolated surface features), **Hesse triage** (list positive/negative/neutral analogy — discard if the negative dominates the load-bearing relations), **ontology consistency** (does the mapping contradict what you know?), and **novelty dedup**. Never let the LLM be the sole judge — the "demand effect" means it will manufacture an analogy on request whether or not real structure exists.
